## Engine — what shipped
- `api/Principal.kt`: `VaultRole {READER, EDITOR}`, `Principal {userId, author, admin, grants, local}`, `UserRegistry` (constant-time key compare, atomic `reload`) — same shape as `AgentRegistry`.
- `api/AppApiAuth.kt`: ONE `intercept(ApplicationCallPipeline.Plugins)` for every `/api/` call: bearer → principal (401), `ADMIN_ROUTES` table (403), vault read grant via `?vault=` (403), non-GET needs EDITOR (403). `NON_VAULT` = vaults|agents|users|me|secrets|update|events. Federated search skips the pre-check and filters per vault in the route. `/health`, `/ready`, `/metrics`, web viewer stay open (unauthenticated by design — stated in the PR; off loopback they expose vault ids/counts).
- **The interceptor matches Ktor's CANONICAL path** (`canonicalPath`: empty segments dropped, each segment percent-decoded) and answers 400 for any non-canonical `/api` path. Review found that Ktor 3.4.3 routes `//api/v1/users` and `/api/v1/%75sers` to the real handlers while `request.path()` is the raw string — the first skipped authentication entirely (and `principal()` fell back to the local ADMIN), the second skipped the admin table. `principal()` now fails closed (500). `isLoopback` reads only `origin.remoteAddress` as an IP literal (the earlier `remoteHost` + `InetAddress.getByName` path did reverse+forward DNS on every keyless request and could be spoofed by a PTR record).
- `localAdmin: true` (default) ⇒ loopback without a key = local UI (admin, author `svod-ui`) — the ENTIRE pre-existing suite runs in this mode, so nothing changed for single-user installs.
- Routes author with `principal().author`; `crossVaultRelink` takes the Principal and skips vaults they cannot WRITE; `/file/links` filters cross-vault backlinks by `canRead`; GET /vaults filtered + `role`; WS events dropped for unreadable `data.vault`. **Every vault-scoped publisher tags `data.vault`** (MCP CONFLICT via `putVault()`, `FileWatcher(vaultId=)` for file.changed/commit.created); only ENGINE_STATUS is untagged.
- `/api/v1/me`, `GET/POST /users`, `PUT/DELETE /users/{id}`, `POST /users/{id}/key` (rotate), `POST /secrets {name,value}` → `{ref: "file:…"}`. `lifecycle/UserController.kt` generates `svk_`+32 random bytes base64url, writes `<configDir>/secrets/user-<id>.key` CREATED 0600 (`security/SecretFiles.kt`), config keeps `file:` ref, registry reloads from `config.toUserSpecs()`. Last-admin guard while `localAdmin=false`; `email: ""` clears. `toUserSpecs()` SKIPS (warn) a user whose keyRef cannot be resolved instead of throwing — one missing key file used to block every admin op and leave disk/memory divergent. `lifecycle/SecretStore.kt` for /secrets (name `^[a-z0-9][a-z0-9_.-]*$`).
- Config: `users[] {userId,name,email?,keyRef,admin,grants[{vault,role}]}`, `localAdmin`, `appApiTls`. Validation: non-loopback host ⇒ appApiTls + mcpTls + users + **`localAdmin=false`**; `localAdmin=false` ⇒ at least one ADMIN user; `keyRef` must start with `env:`/`file:`/`keychain:` (a bare key would be echoed by GET /users). `AppApiServer.start()` uses Netty `sslConnector` when `Config.tls` set (CIO cannot do TLS), CIO otherwise. `dist/secrets/` is git-ignored (the live config lives in the repo, so key files would too).
- Tests: `PrincipalAuthTest` (14, two-vault fixture with users IN CONFIG), `UserAdminTest` (8), `SharedEngineConfigTest` (5), `AppApiTlsTest` (1). Suite 439 tests / 11 skipped / 0 failures. Negative verification: canonical-path check removed (1 fails), canRead⇒true (4), admin gate removed (1), write gate removed (1), rotate without reload (1).

## App — what shipped
- `Networking/VaultKey.swift`: remote vault key `<vault>@<profile>` (last `@` wins; `:` stays GlobalNoteRef's). Local vault ids unchanged.
- `Networking/MultiEngineClient.swift`: `SvodClient` router — `local` + `remotes[profileId]`; `setActiveVault(key)` picks the engine (remote always addressed with the bare id, never nil); `target(vault)` for explicit-vault overloads; `vaults()` merges + rekeys CONCURRENTLY (`withTaskGroup`, sorted by name; a dead remote lands in `unreachable`); `events()` merges streams, remote events re-tagged with the key (default looked up PER EVENT), untagged LOCAL events tagged with the local default (else EngineModel's "nil ⇒ active vault" gate applies them to a remote vault); **`health/ready/updateCheck/updateApply` always local** (verifier caught Settings → Updates about to apply an update on the company's engine). `createVault` always local; `deleteVault`/`importVault`/`registerSource` throw `.notImplemented(msg)` for a remote target (paths on this Mac). `localBaseURL` for the offline pane.
- `App/EngineProfiles.swift`: `EngineProfileStore(defaults:secretsDir:)` — profiles JSON in `svod.settings.engineProfiles`, key in `engine-<id>.key` 0600. `AppModel.live()` composes `MultiEngineClient(local: LiveSvodClient(), profiles:)`; `reloadEngines()` reconfigures + reconnects + reloads vaults. `didSwitchVault()` re-runs `engine.loadMeta()` (version gates follow the ACTIVE engine) and forces preview for a read-only vault.
- `LiveSvodClient(bearerKey:)` sends `Authorization: Bearer` on get/send/sendNoBody/sendNoResult AND the WS upgrade; `basePath(of:)` keeps a reverse-proxy prefix in front of every API path.
- UI: Settings → Connection "Central engines" (`AddEngineSheet` tests via `/me` before saving), Settings → Members (`MembersSettingsView` + `MembersModel`, key shown once in `KeyRevealSheet`, per-vault role picker, rotate/revoke), `VaultModel.wireKey` + `vaultGroups` (grouped by engineId, labelled by name; `read-only` pill; no delete menu for a remote vault), `EditorModel.isReadOnly` guard + banner + disabled preview toggle, Sync&Backup `remoteTokenFlow` (`POST /secrets` then `PUT /settings/backup`), agent tokens on a remote vault via `POST /secrets`, gated `apiVersionAtLeast(0,30)`.
- Tests: `VaultKeyTests`, `EngineProfileStoreTests`, `MultiEngineClientTests` (subclass `MockSvodClient` — works under `@testable`; 11 incl. self-update routing, remote refusals, untagged tagging, basePath), `MembersModelTests` (`ReaderMock` non-admin that fails if /users is requested) — 53 total green, every store test injects `UserDefaults(suiteName:)`.
- NOT visually verified in the running app (release 0.2.22 was open; a second instance would share its UserDefaults).

## Gotchas hit this sprint
- Kotlin nests block comments: a KDoc containing `` `/api/*` `` is an **unclosed comment** compile error. Write `/api/` instead.
- `@Test fun x() = runBlocking { … }` ending in a non-Unit expression is silently NOT run (again). `UserAdminTest` showed 3 of 6 until `(): Unit = runBlocking`.
- A test fixture that seeds `UserRegistry` directly (not via config) loses those users on the first controller mutation, because the controller reloads the registry FROM CONFIG. Seed config with `file:` key refs.
- Ktor 3.4.3: `intercept` lambda needs `import io.ktor.server.application.call`. **Ktor routing normalises the path (drops empty segments, percent-decodes) but `request.path()` is raw** — any path-based auth must canonicalise first.
- `PUT /file` on an EXISTING note and `POST /file/move` both 409 without `expectedRevision` — read `engine.read(path)!!.revision` first in tests.
- `GraphRagUnitTest` hardcodes `CURRENT_CONTRACT_VERSION` — bump it with every contract bump.
- The sandboxed `xcodebuild` leaves `TemporaryDirectory.*`, `_Users_katsarov_*.lock`, `swift-generated-sources/` in the app repo root — delete after each run (`find -maxdepth 1 … -exec rm -r {} +`; a plain `rm -rf /abs/path` is blocked by the hook). `-quiet` logs have no assertion text, only "failed" lines.
- `MultiEngineClient.events()` merged stream ENDS when the local stream ends (never in production; instantly with a mock) — a test must not expect remote events to arrive first.
- `@testable import` lets tests subclass a `public` non-final class and override `public` methods (used for `EngineMock`, `ReaderMock`).
- ICU transliteration: "Мария Петрова" → slug `maria-petrova` (not `mariya`).
